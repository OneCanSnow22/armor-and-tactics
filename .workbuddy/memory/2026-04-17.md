## 栈系统排查：fresh_cards ban 异常
- `fresh_cards` 在 `cope_with_card_clicked` 中未被 await，与 `applay_stack` 的异步动画存在竞态
- 疑似场景：新卡可覆盖栈堆但被 ban，需用户提供具体复现场景确认

## 栈系统排查：四个累积BUG根因
1. **动画不更新**：`clear_stackBar` 的 tween 和 `applay_stack` 的 tween 交叉操作同一 stackBar 属性
2. **启用错卡牌**：`fresh_cards` 遍历含离场中卡牌，用已覆盖的 stackArray 状态判断
3. **新卡被锁住**：`stackArray` 存卡牌子节点引用而非独立数据，`clear_stackBar` 反向修改卡牌 stack_mode
4. **翻页按钮异常**：打出卡后没更新 `total_pages`，禁用条件 `==7` 应改为 `<=7`

## 栈系统漏洞
- `is_coverd` 里 `list` 只有 Melee/Shoot/Shelling 三个 key，`Empty` 的判断必须放在 `list[...]` 访问之前，否则 Empty 时访问不存在的 key 会崩
- `applay_stack` 先赋值再判断 null，else 永远不执行
- `applay_stack` 有 await，`cope_with_card_clicked` 调用时需要 await 才能保证动画后执行 function

## Melee._init 变量名遮蔽 bug
- `class Melee extends Attack` 的 `_init(damage:int, info:int)` 里参数名与父类成员变量同名
- `damage = damage` 赋值给参数自身，父类 `self.damage` 始终为 0
- 修法：参数改名并调 `super._init(p_damage)`
