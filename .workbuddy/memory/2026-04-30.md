## function_list 与 UI 节点脱节问题（重要教训）

- **根因**：`function_list` 存的是数据引用，`line1/line2` 存的是 UI 节点。`Card.Blank.new()` 替换 function_list 后，UI 上的旧节点（Lock）没人移除，导致数据层和 UI 层不一致。
- **错误修复方向**：用 `_refresh_card_functions` 清空容器再重新 add_child——复杂且容易出边界问题。
- **正确修复方向**：`card.display()` 改为从 UI 容器（`line1/line2.get_children()`）取节点，用 `function_list` 数据同步 mode 等属性，再调 `display()`。这样始终操作的是 UI 上实际挂着的节点，不会脱节。
- **教训**：不要在数据层替换对象引用然后期望 UI 自动跟着变。应该保持 UI 节点稳定，用数据驱动 UI 属性更新。
- `_refresh_card_functions` 已同步在 `show_card_list`（workshop/cmd）和 `put_blank_to_basket` 中调用，确保 function UI 与数据层同步。
- `tear_down` 实现：拆除卡牌，有效模组（非 Lock/Blank）存入 `functions: Array[function]`，从 `Profile.Deck` 移除。
- `can_be_tear_down` 时机：`open_rewrite` 初始化时判断，`tear_down` 每次拆完后判断，`_tear_cost()` 统一公式 `70*(1+0.5*times)`。
- `who_is_the_target`：Blank 手动 load 纹理（`display()` 对 Blank 直接 return）；`select_function._set_function` 对 Blank 单独处理。
